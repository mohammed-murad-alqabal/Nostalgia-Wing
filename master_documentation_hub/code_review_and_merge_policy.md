# Code Review & Merge Policy

## المشروع: جناح الحنين (Nostalgia Wing)

---

## 🎯 الغرض (Purpose)

ضمان أن كل سطر كود يدخل المستودع الماستر يلتزم بأعلى معايير الجودة، الأمان، والنقاء الهيكلي.

## 🛠️ قواعد مراجعة الكود (Review Rules)

1. **نقاء المسار**: لا يتم دمج أي كود يحتوي على ملفات بناء، ملفات مؤقتة، أو ملفات بيئة عمل.
2. **التحليل الثابت (Static Analysis)**: يجب أن يمر الكود باختبار `flutter analyze` بصفر أخطاء وصفر تحذيرات.
3. **التوثيق**: كل دالة أو صنف جديد يجب أن يحتوي على توثيق واضح (Comments / Docstrings).

## 🚪 بوابات الجودة (Quality Gates)

قبل الدمج (Merge)، يجب استيفاء الشروط التالية:

- [ ] نجاح بناء المشروع (Build) على جميع المنصات المدعومة.
- [ ] مرور كافة اختبارات الوحدة (Unit Tests).
- [ ] مطابقة التسمية لمعيار `snake_case` العالمي.
- [ ] خلو الكود من أي "ضوضاء" (Debug prints / TODOs غير موثقة).

## 🔄 استراتيجية الدمج (Branching & Merge)

- **Main/Master Branch**: هو الفرع المقدس الذي يحتوي دائماً على نسخة "النقاء الماسي" القابلة للنشر.
- **Merge Criteria**: يتم الدمج حصراً عبر `Pull Requests` بعد مراجعة دقيقة من الكيان الهندسي الاستراتيجي.
- **Flattening History**: يفضل استخدام `Squash and Merge` للحفاظ على تاريخ Git نظيفاً ومركزاً.
