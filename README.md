## نقطة البداية الرسمية



المصدر الرسمي لخريطة الوثائق وحالاتها هو [دليل الوثائق](docs/README.md). قبل تعديل المعمارية أو إضافة ميزة، راجع [حالة النظام الحالية](docs/current/system-status.md) و[المعمارية الحالية](docs/current/architecture.md). أما المواصفات المستقبلية فتوجد في `.kiro/specs/` ولا تُعد ميزات منفذة إلا إذا كان لها مسار كود واختبار ونتيجة تحقق مرتبطة بعملية دمج.



## هيكل المستودع



| المسار | الغرض والسلطة |

|---|---|

| [`active_source_wing/`](active_source_wing) | الكود التنفيذي الفعلي لتطبيق Flutter؛ هو مصدر الحقيقة لسلوك وقت التشغيل والتبعيات |

| [`docs/current/`](docs/current) | الوصف المعتمد للحالة الحالية، ويجب أن يطابق الكود والاختبارات |

| [`docs/proposed/`](docs/proposed) | التصاميم والميزات المستقبلية غير المنفذة |

| [`docs/decisions/`](docs/decisions) | قرارات المعمارية والهندسة بصيغة ADR |

| [`docs/guides/`](docs/guides) | إرشادات التطوير والتشغيل والمساهمة |

| [`docs/archive/`](docs/archive) | وثائق تاريخية غير صالحة كمصدر للحالة الحالية |

| [`.kiro/specs/`](.kiro/specs) | مواصفات ميزات؛ لكل مواصفة حالة وتتبع تنفيذ واختبار |



## التشغيل والتطوير



للبدء:



```bash

cd active_source_wing

flutter pub get

flutter analyze

flutter test

flutter run

```



يجب تنفيذ فحوص حوكمة الوثائق من جذر المستودع:



```bash

python3 scripts/verify_documentation_governance.py

```



## مبادئ الحالة والسلطة



يجب عدم وصف خدمة أو تقنية بأنها **Current** لمجرد ورودها في وثيقة تصميم. التبعيات والكود والاختبارات ونتائج CI هي الأدلة التنفيذية. التقنيات غير الموجودة في الكود، مثل Backend أو LLM أو Signal Protocol، تُذكر في وثائق `Proposed` فقط إلى أن تُنفذ وتُختبر.



**الحالة الراهنة:** تطوير نشط، مع فصل موثق بين Current وProposed وArchived.
