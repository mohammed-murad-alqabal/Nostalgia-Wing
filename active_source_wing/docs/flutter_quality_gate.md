# بوابة جودة Flutter قبل الدمج

**إعداد فريق تطوير مشروع جناح الحنين**

توحّد بوابة الجودة تنفيذ فحص تنسيق Dart و`flutter analyze` و`flutter test` حتى ينتج الفحص المحلي وسير العمل البعيد النتيجة نفسها. يقع السكربت المصدري في `tool/verify_flutter.sh` ويعمل من أي دليل لأنّه يحدد مجلد المشروع تلقائياً.

## مسارات الحماية

| المسار | متى يعمل | ما يحميه | التفعيل |
|---|---|---|---|
| فحص محلي | قبل إنشاء commit دمج محلي | يمنع الدمج المحلي إذا فشل التنسيق أو التحليل أو الاختبارات | يُفعّل مرة واحدة لكل نسخة مستودع. |
| فحص بعيد | عند طلب دمج أو دفع إلى `main` و`develop` | يمنع تمرير تغييرات غير مفحوصة إلى الفرع المحمي | يُفرض من إعدادات حماية الفرع. |

> الفحص المحلي يحسّن سرعة الملاحظات للمطوّر، لكنه ليس حماية كافية بمفرده؛ يمكن تجاوزه محلياً أو قد لا يفعّله مطوّر جديد. لذلك يجب جعل فحص سير العمل البعيد شرطاً إلزامياً للدمج.

## الاستخدام المحلي

فعّل خطاف الدمج مرة واحدة من جذر المستودع:

```bash
bash scripts/install_flutter_quality_hook.sh
```

شغّل البوابة يدوياً في أي وقت من مجلد Flutter أو من جذر المستودع:

```bash
bash active_source_wing/tool/verify_flutter.sh
```

يتحقق السكربت من توفر Flutter، ثم ينفذ بالترتيب التالي:

```bash
flutter pub get
dart format --output=none --set-exit-if-changed lib test integration_test
flutter analyze
flutter test
```

يتوقف السكربت فور فشل أي خطوة ويعيد رمز خروج غير صفري؛ لذلك يوقف خطاف الدمج أو مهمة التحقق البعيدة تلقائياً.

## فرض النتيجة قبل الدمج

أضف قاعدة حماية لكل من `main` و`develop` في إعدادات المستودع على GitHub. فعّل «Require a pull request before merging» و«Require status checks to pass before merging»، ثم اختر فحص الحالة:

```text
Flutter CI / build
```

يمكن أيضاً تفعيل طلب مراجعة واحدة على الأقل، وفرض أن تكون المحادثات محلولة، ومنع تجاوز القاعدة للمشرفين إذا كان الهدف منع أي دمج غير مفحوص. بعد الحفظ، لن يكتمل دمج طلبات السحب إلى الفرع المحمي قبل نجاح بوابة الجودة.

## استكشاف الأعطال

| العرض | الإجراء |
|---|---|
| `Flutter SDK غير متاح` | ثبّت Flutter stable وتأكد من ظهور `flutter --version` في الطرفية. |
| فشل `flutter pub get` | راجع الاتصال والاعتماديات في `pubspec.yaml` وملف القفل. |
| فشل التنسيق | شغّل `dart format lib test integration_test` وراجع الفروقات الناتجة قبل إعادة تشغيل البوابة. |
| فشل التحليل | عالج أخطاء `flutter analyze` قبل الدمج؛ لا تستخدم `--no-fatal-infos` لإخفاء مشكلات جديدة بلا قرار موثق. |
| فشل الاختبارات | شغّل الاختبار المحدد محلياً، أصلح السبب، ثم شغّل البوابة كاملة. |
| الخطاف لا يعمل | نفذ `bash scripts/install_flutter_quality_hook.sh` وتحقق من `git config --get core.hooksPath`، الذي يجب أن يعرض `.githooks`. |

## التحقق الموسع والإصدار

يوثق الملف [تشغيل CI/CD](cicd_operations.md) خطوات تفعيل حماية `main` و`develop`، وتشغيل `Release validation`، وحدود artifact الحالي قبل اعتماد توقيع إنتاجي أو نشر متجر التطبيقات.

## حدود متعمدة

لا يشغل هذا السكربت اختبارات التكامل تلقائياً، لأن تلك الاختبارات تحتاج عادةً محاكياً أو جهازاً ومنصة تشغيل مناسبة. يجب إضافتها كمهمة منفصلة في مسار الإصدار بعد تثبيت بيئة Android/iOS، ولا ينبغي اعتبارها بديلاً عن اختبارات الوحدة والواجهات السريعة.
