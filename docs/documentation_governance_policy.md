# Documentation Governance Policy

## المشروع: جناح الحنين (Nostalgia Wing)

---

## 🎯 الغرض (Purpose)

تحديد إطار عمل صارم لإدارة، مراجعة، وتحديث الوثائق الاستراتيجية والتقنية لضمان دقتها، سريتها، وتوافقها مع "عقيدة الحصن الحي".

## 👤 الملكية والمسؤوليات (Ownership & Roles)

1.  **مالك المستند (Document Owner)**: هو الكيان أو الفرد المسؤول عن دقة المحتوى (مثلاً: الكيان الهندسي للوثائق التقنية).
2.  **سلطة الاعتماد (Approval Authority)**: الجهة التي تمنح الصبغة الرسمية للوثيقة (الزوج/المؤسس).
3.  **المراجع (Reviewer)**: الوكيل الذكي أو المهندس الاستراتيجي المسؤول عن فحص الاتساق.

## 🔄 دورة حياة الوثيقة (Document Lifecycle)

| المرحلة              | الإجراء                                     | التكرار                     |
| :------------------- | :------------------------------------------ | :-------------------------- |
| **المراجعة الدورية** | فحص مدى صلة الوثيقة بالواقع الحالي للمشروع. | كل 3 أشهر                   |
| **التحديث الطارئ**   | عند تغيير في المعمارية أو السياسات الأمنية. | فوري                        |
| **الأرشفة**          | نقل النسخ القديمة إلى `purified_archives`.  | عند صدور نسخة "ماستر" جديدة |

## 🏷️ قواعد التسمية والإصدار (Versioning Rules)

1.  **اللغة**: الإنجليزية `snake_case` للمسارات (Paths)، والعربية/الإنجليزية للمحتوى الداخلي.
2.  **نظام الإصدارات**:
    - `vX.Y`: (مثلاً `v1.0` للإصدارات المستقرة، `v0.1` للمسودات).
3.  **التذييل**: يجب أن تحتوي كل وثيقة استراتيجية على تاريخ الإنتاج، رقم الإصدار، واسم المؤلف.

## 🔒 السرية والوصول (Access Control)

- **الوثائق المعرفية**: (المواثيق، سجلات التهديدات) تشفر ولا تُنشر خارج البيئة المؤمنة.
- **وثائق التشغيل**: متاحة للفريق التقني المصرح له فقط.
